# Extracting multiple parcellations

Selecting multiple parcellations increases runtime and the number of output columns; it also increases image counts if QC is enabled.
Choose atlases based on your research question rather than running every atlas by default.

## Add atlases in stages

First read the built-in FreeSurfer parcellations:

```bash
fsharvest INPUT OUTPUT --jobs 12 --atlases dk68 destrieux
```

Check the outputs and column names. Once the input directory and FreeSurfer environment are working, add external atlases that require projection:

```bash
fsharvest INPUT OUTPUT --jobs 12 \
  --atlases dk68 destrieux schaefer100 schaefer400 glasser360
```

Validated caches can be reused in subsequent runs. External-atlas `.annot` and `.stats` files are stored in each subject's `per_subject/` directory.

## Using your own annot files {#custom-annot}

Built-in atlas names and custom JSON definitions share the `--atlases` option and can be combined in one run:

```bash
fsharvest INPUT OUTPUT --atlases dk68 schaefer100 /path/to/lab-atlas.json \
  --qc-plots --qc-atlases lab
```

To extract only the custom atlas, use `--atlases /path/to/lab-atlas.json`. The contents of `lab-atlas.json` are:

```json
{
  "key": "lab",
  "display_name": "Custom laboratory atlas",
  "source_subject": "fsaverage5",
  "annotations": {
    "lh": "lh.lab.annot",
    "rh": "rh.lab.annot"
  },
  "excluded_regions": ["unknown", "corpuscallosum"]
}
```

- Supply both hemispheres. Paths may be absolute or relative to the JSON file.
- `key` controls output filenames and QC selection. Start with an ASCII letter or digit and use only ASCII letters, digits, `_`, or `-`. It must not duplicate a built-in name or another atlas selected in the same run.
- Set `source_subject` explicitly to `fsaverage5` or `fsaverage`. Install that template under `FREESURFER_HOME/subjects/`.
- `display_name` is optional and defaults to `key`.
- The program automatically excludes `unknown`, `Unknown`, `corpuscallosum`, and `Medial_wall`, which FreeSurfer omits from its statistics. Optional `excluded_regions` adds other exact label names to exclude.

FSHarvest reads annotation color-table entries actually assigned to source-template vertices. After exclusions, it derives
the region names and counts for each hemisphere. Unused color-table entries are ignored, hemisphere counts may differ,
and names may contain spaces. Every retained region must appear in the generated statistics; a real region lost during
projection still triggers an error. You do not need to write separate manifest or checksum files.

Named external atlases load the bundled annotations and metadata; custom JSON loads the specified annotations.
Both follow validation → projection to subjects → statistics generation → extraction and aggregation, with optional QC.
DK68 and Destrieux instead read the statistics already generated by recon-all.

Vertex-count checks can detect a file that does not match a template, but cannot infer its source space.
These inputs must be **template-space** annotations, not individual subjects' native-space annotations.
Custom atlases always use the files specified in the JSON as projection sources, not same-named files in subject directories.
Validated caches in the output directory can still be reused.

Results use `key`, for example `wide/lab.tsv` and `per_subject/SUBJECT/label/lh.lab.annot`.
`atlas_manifest.tsv` records paths and expected left/right region counts; `run_metadata.json` retains full definitions and region lists.

## Choose a parcellation scale

- Schaefer100: coarser network-scale regions and fewer wide-table columns.
- Schaefer400: a commonly used intermediate scale.
- Schaefer1000: finer regions, with more model variables and a greater multiple-comparison burden.
- Glasser360: a multimodal cortical parcellation.
- Economo: based on cytoarchitecture.
- DK308 and Vos de Wael 300: both subdivide anatomical boundaries, but are distinct parcellations.

## Distinguish columns from different atlases

Each atlas has its own table at `wide/ATLAS.tsv`. Columns in `all_features_wide.tsv` include an atlas prefix:

```text
dk68__L_bankssts_thickavg
schaefer400__L_7Networks_LH_Vis_1_thickavg
```

## Review checklist

1. Check each atlas's expected region counts and complete-subject count in `atlas_manifest.tsv`.
2. Inspect each subject's overall `status` and `errors` in `subjects.tsv`.
3. Locate atlas and hemisphere failures in per-subject `status.json` and `extract.log`.
4. Review QC images for several representative subjects for each external atlas.
5. Record atlas names, scales, sources, and FreeSurfer versions in your methods.

::: warning There is no separate per-atlas status table yet
`subjects.tsv` is not a subject × atlas status table. Failure of a selected atlas can make overall subject status `PARTIAL`
or `FAILED`, but successfully parsed data with unambiguous identifiers still enter the summary tables.
Missing-region values remain empty. Consult `errors`, `status.json`, and `extract.log` for details.
See [which results enter the summary tables](../guide/outputs#aggregation).
:::
